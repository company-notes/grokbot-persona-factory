# Coding rules

Follow the included `CODE_PRINCIPLES.md` and `TESTING.md` for all code and tests. Prioritize DRY, OO encapsulation, separation of concerns, early returns, fail-fast exceptions, camelCase naming, always-braced JavaScript control flow, and Rule #20 meaningful vertical spacing. No copy-paste service logic across UI and API. Fix bugs with regression test red → green (不貳過).

The architecture and API contracts are in `docs/ARCHITECTURE.md` and `docs/API.md`. Do not hardcode the company's current products, current employees or ephemeral organizational relationships into generic Presets.
